# Shell bytes and locale boundaries

[POSIX.1-2024 shell parameters](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_05) allow arbitrary non-NUL bytes in values. [Word expansion](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_06) distinguishes byte-preserving operations from character-oriented operations. In particular, joining arguments and forwarding external argv must not replace invalid UTF-8; character classes and collation are separate locale work. Keep the existing command-substitution NUL diagnostic and distinguish a NUL `read` delimiter from a stored NUL value.

Filesystem matches and external argv remain in native form through `exec`. Expansion fragments, positional arguments, and scalar variables preserve bytes, including through native worker payloads. `read` and command substitution preserve non-UTF-8 data, reject embedded NUL, and keep their existing delimiter and trailing-newline semantics. Text consumers still include shell source, most builtin and function operands, pathname redirection operands, indexed arrays, the editor, history, and agent JSON. Diagnostic rendering is not a way to recover original bytes.

[POSIX `sh` locale variables](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/sh.html#tag_20_110_08) and the [pattern rules](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_14) distinguish character interpretation from collation. For pattern operations, zledsh selects each category from nonempty `LC_ALL`, the category variable, then `LANG`, using C when unset or unavailable. Selection is evaluated at expansion time; it does not change source tokenization. Matching and ordering use the host locale data. Pathname collation uses bytewise tie-breaking; ordering of names invalid in the chosen locale is not portable. Field splitting and parameter trimming boundaries still use UTF-8 units rather than a general locale decoder. Regex matching and diagnostic language are unchanged.
