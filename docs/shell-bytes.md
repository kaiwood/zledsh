# Shell bytes and locale boundaries

[POSIX.1-2024 shell parameters](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_05) allow arbitrary non-NUL bytes in values. [Word expansion](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_06) distinguishes byte-preserving operations from character-oriented operations. In particular, joining arguments and forwarding external argv must not replace invalid UTF-8; character classes and collation are separate locale work. Keep the existing command-substitution NUL diagnostic and distinguish a NUL `read` delimiter from a stored NUL value.

The first slice keeps filesystem matches and external argv in native `OsString` form through `exec`. Native pipeline and subshell workers expand their own words, so glob matches do not have to cross a serialized text boundary. Builtin and function operands still cross a UTF-8 boundary. Positional arguments were converted at CLI entry; expansion fragments, scalar values, and arguments in worker payloads are text. `read` and substitution capture currently convert their byte buffers to UTF-8. These paths need a separate value representation before the remaining byte workflows can be supported without replacement. Keep shell grammar, history, the editor, and agent JSON text boundaries explicit.
